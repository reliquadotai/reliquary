# Mining orders (Batch and Evals)

Customers' Batch and Evals orders are generated by miners and paid per verified token. Everything a miner needs
is on one address: **`https://api.reliqua.ai`**.

## Install and update

From a clone of this repository, in a Python 3.12 venv made by [uv](https://docs.astral.sh/uv/)
(`uv venv --python 3.12 .venv && source .venv/bin/activate`):

```sh
git pull && uv pip install -e ".[sandbox-miner]" vllm==0.30.0 --override miner-overrides.txt && reliquary miner-envs --sync
```

The same line installs and updates. vLLM 0.30.0 is the only engine the forced draw accepts. It declares `mcp>=2`,
while verifiers 0.3.1, which the env packages run on, declares `mcp<2` and needs it (it imports mcp 1's `FastMCP`),
so pip finds no solution. vLLM itself imports mcp only for `vllm serve`'s MCP tool server, which the miner never
starts: `miner-overrides.txt` replaces vLLM's bound with verifiers', which uv applies and pip cannot. `uv pip check`
(or `pip check`) then reports `vllm ... requires mcp>=2.0.0,<3.0.0`: that line is expected, any other is not.
`reliquary miner-envs` refuses the bridge when mcp 2 is installed (a plain `pip install vllm` lifts it), and
`--sync` brings mcp 1 back. `sandbox-miner` brings the env packages agentic orders pin, from git at their
commits (the validator checks the commit pip records): SWE-bench Verified (`reliquary-swe`), SWE-bench Pro
(`reliquary-swebench-pro`), DeepSWE (`reliquary-deepswe`), Terminal-Bench 2.1 (`reliquary-terminal-bench`),
AutomationBench (`reliquary-automationbench`), with the reliquary-sandbox bridge and the reliquary-harness.
pip does not reinstall a git package whose commit moved under the same version, so
`reliquary miner-envs --sync` reinstalls the ones that are missing or stale (with uv when it is on the PATH,
applying the same mcp override). Single-turn orders (LiveCodeBench,
GraphWalks, MRCR, ...) need none of them: their prompts come from the order.

`reliquary miner-envs` alone prints which order families this install serves, and why the others are refused.
The miner runs the same check when it starts (and the sync, unless `--no-sync-envs`) and logs it. The env packages
are built for Python 3.12: under another Python they are skipped, and their orders refused.

## Run it

```sh
reliquary corpus mine \
  --validator-url https://api.reliqua.ai \
  --wallet-name YOUR_WALLET --hotkey YOUR_HOTKEY \
  --ask-alpha-per-mtoken 0.4 --ask-capacity 8
```

Without `--job-id` the miner follows the orders by itself: it picks an open order (one on the model it already
has first), mines it in its own process, and moves to the next when it ends. While no order is open it downloads
the model of the one that is starting. Pass `--job-id <id>` to mine one order only.

## The order list

`GET https://api.reliqua.ai/corpus/jobs`

```json
{"jobs": ["order-gen-..."],
 "orders": [{"job_id": "order-gen-...", "state": "open", "model": "org/name", "revision": "<40 hex>",
             "prompts": 8765, "samples_per_prompt": 1, "max_new_tokens": 8192,
             "pricing": "auction", "auction": {"price_alpha_per_mtoken": 0.31, "ceiling_alpha_per_mtoken": 0.58}}]}
```

| `state` | Meaning |
|---|---|
| `starting` | Its audit card is loading the model (a few minutes to ~20 for a 27B). Download the model now. |
| `open` | Mine it. |
| `paused` | Admission stopped for now. |
| `draining` | Generation is over; its last submissions are audited and paid. Nothing new is accepted. |

`jobs` lists the ids open right now. `/corpus/tasks` is the registry's history of every task ever declared, not a
list of what to mine.

## How orders pay: the price auction

On an order with `"pricing": "auction"`:

- **Your offer.** `--ask-alpha-per-mtoken` is the alpha per million verified tokens you work for, at most the
  order's ceiling. `--ask-capacity` is how many samples you can have in flight at once.
- **Cheapest first.** Work goes to the lowest offers first, up to each one's capacity. The validator sends out
  only as much work as it can audit.
- **The price of the moment.** Each lease is paid the price of the moment it was granted: the dearest offer
  getting work at that instant, never less than your own offer. Everyone working at the same moment is paid the
  same price. An offer under your real cost only wins you work at moments that pay less than that cost, so
  offer your real cost.
- **Keep your word.** A lease you take and do not deliver is charged against your next payouts, and halves your
  capacity for an hour.
- **Follow the draw.** A sample that does not follow the order's forced draw (another model, a heavy quantisation,
  edited tokens) fails its audit. A hotkey with a confirmed failure gets no new lease on that order until its
  suspicion ends (`miner_suspect`, with the time); `GET /corpus/jobs/<job_id>/miners/<hotkey>` shows why.
- **Your setup.** Lease up to 256 samples per request, with any engine and batch size.

Without an offer you get no work on an auctioned order. `GET /corpus/jobs/<job_id>/auction` shows its current
price, budget and audit queue.

## Your own numbers

- `GET /corpus/jobs/<job_id>/miners/<hotkey>`: your submissions, verdicts and pay on an order.
- `GET /corpus/pay`: what each order pays.
